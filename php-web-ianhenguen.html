    3. PHP Web 编程入门

    3.1. PHP 编程

    在此需重申，PHP 本身是一种独立的编程语言，虽然它主要用于 Web 应用程序开发，但也适用于其他场景。文档《PHP by Example》（网址：http://shiva.istia.univ-angers.fr/~tahe/pub/php/php.pdf）介绍了该语言的基础知识。本文假设您已掌握这些基础知识。 让我们通过一个简单示例演示如何在 Windows 上运行 PHP 程序。以下代码已保存为 coucou.php。

    <?php
    echo "coucou";
?>

    该程序在 Windows 命令提示符窗口中运行：

    
dos>"e:\program files\easyphp\php\php.exe" coucou.php
X-Powered-By: PHP/4.3.0-dev
Content-type: text/html
 
coucou

    请注意，PHP 解释器默认会发送以下内容：

    • PHP 解释器是 php.exe，通常位于软件安装目录的 <php> 目录中。
    • HTTP 头部 X-Powered-By 和 Content-type:
    • 将 HTTP 头部与文档其余部分分隔开的空行
    • 文档主体（此处为 echo 函数输出的文本）

    3.2. PHP 解释器的配置文件

    PHP 解释器的行为通过名为 php.ini 的配置文件进行配置，在 Windows 系统中，该文件位于 Windows 目录内。这是一个相当大的文件；在 Windows 系统中，PHP 4.2 版本的该文件包含近 1,000 行，所幸其中四分之三为注释。让我们来查看一些 PHP 的配置设置：

    short_open_tag = On
    允许在 <? > 标签之间包含指令。如果设置为 Off，则必须在 <?php ... > 之间包含
    asp_tags = Off
    当设置为 On 时，允许使用 ASP（Active Server Pages）所用的 <% =变量 %> 语法
    expose_php = On
    启用发送 HTTP 头部 X-Powered-By: PHP/4.3.0-dev。若设置为 Off，则移除此头部。
    error_reporting  =  E_ALL & ~E_NOTICE
    设置错误报告的范围。在此设置下，除运行时警告（~E_NOTICE）外的所有错误（E_ALL）都将被报告
    display_errors = Off
    当设置为 on 时，会将错误信息包含在发送给客户端的 HTML 输出中。因此这些错误会在浏览器中显示。建议将此选项设置为 off。
    log_errors = On
    错误将被记录到文件中
    track_errors = On
    将最近发生的错误存储在 $php_errormsg 变量中
    error_log = E:\Program Files\EasyPHP\php\errors.log
    设置错误日志文件（若 log_errors=on）
    register_globals = Off
    当设置为 On 时，许多变量将变为全局变量。这被视为一个安全漏洞。
    default_mimetype = "text/html"
    生成默认的 HTTP 头部：Content-type: text/html
    include_path    =".;E:\Program Files\EasyPHP\php\pear\"
    将用于搜索 include 或 require 指令所需文件的目录列表
    session.save_path = /temp
    用于保存各种活动会话文件的目录。此处的磁盘即 PHP 的安装磁盘。此处 /temp 指代 e:\temp

    此配置文件会影响 PHP 程序的可移植性。实际上，如果一个 Web 应用程序需要从 Web 表单中获取 C 字段的值，它可以通过多种方式实现，具体取决于 register_globals 配置变量是设置为 on 还是 off：

    • off：将根据客户端提交表单值所使用的请求方法（GET/POST），通过 $HTTP_GET_VARS["C"]、_GET["C"]、$HTTP_POST_VARS["C"] 或 $_POST["C"] 获取该值
    • 开启：与上述情况相同，此外还有 $C，因为字段 C 的值已被定义为与字段同名的全局变量

    如果开发人员因所使用的 Web/PHP 服务器将 *register\_globals* 变量设置为 on，而编写了使用 $C 语法的程序，那么当该程序被迁移到将该变量设置为 off 的 Web/PHP 服务器时，该程序将无法运行。因此，我们应致力于编写避免依赖 Web/PHP 服务器配置的程序。

    3.3. 运行时配置 PHP

    为了提高 PHP 程序的可移植性，您可以自行设置某些 PHP 配置变量。这些变量在程序执行期间被修改，且仅对该程序生效。在此过程中，有两个函数非常有用：

    ini_get("confVariable")
    返回配置变量 confVariable 的值
    ini_set("confVariable", "value")
    设置配置变量 confVariable 的值

    以下是一个设置 track_errors 配置变量值的示例：

    <?php
     // value of the track_errors configuration variable
    echo "track_errors=".ini_get("track_errors")."\n";
  // change this value
  ini_set("track_errors","off");
   // check
  echo "track_errors=".ini_get("track_errors")."\n";
?>

    执行后，将得到以下结果：

    E:\data\serge\web\php\poly\intro>"E:\Program Files\EasyPHP\php\php.exe" conf1.php
Content-type: text/html

track_errors=1
track_errors=off

    配置变量 track_errors 的初始值为 1（即开启）。我们将它设置为关闭。请注意，如果我们的应用程序依赖于某些配置变量的值，那么在程序内部初始化这些变量是明智之举。

    3.4. 示例的执行环境

    本讲义中的示例将采用以下配置运行：

    • 运行 Windows 2000 的 PC
    • Apache 1.3 服务器
    • PHP 4.3

    Apache 服务器的配置在 httpd.conf 文件中指定。以下几行代码指示 Apache 将 PHP 加载为集成模块，并将任何针对具有特定文件扩展名（包括 .php）的文档的请求传递给 PHP 解释器。这是我们将用于 PHP 程序的默认扩展名。

    LoadModule php4_module "E:/Program Files/EasyPHP/php/php4apache.dll"
AddModule mod_php4.c
AddType application/x-httpd-php .phtml .pwml .php3 .php4 .php .php2 .inc

    此外，我们还为 Apache 定义了一个名为“poly”的别名：

    Alias "/poly/" "e:/data/serge/web/php/poly/"
<Directory "e:/data/serge/web/php/poly">
  Options Indexes FollowSymLinks Includes
  AllowOverride All
  # Order allow,deny
  Allow from all
</Directory>

    我们将路径 e:/data/serge/web/php/poly 称为 <poly>。如果我们想通过浏览器向 Apache 服务器请求文档 doc.php，将使用 URL http://localhost/poly/doc.php。Apache 服务器会识别 URL 中的别名 poly，并将其与文档 <poly>\doc.php 关联起来。

    • 可以使用 isset(data) 函数来检测一段数据是否存在，如果数据存在，该函数返回 true，否则返回 false。
    • nomage.php 应用程序创建了三个变量：$name 用于存储表单名称，$age 用于存储年龄，$post 用于指示值是否已被“提交”。这三个变量会被传递给 nomage-p1.php 页面。请注意，虽然该页面参与了向客户端生成响应的过程，但客户端对此并不知情。从客户端的角度来看，响应来自 nomage.php 应用程序。
    • 客户端首次请求 nomage.php 应用程序时，$post 被设置为 false。这是因为在首次调用期间，没有表单值被发送至服务器。

    3.7. 获取 Web 客户端发送的 HTTP 头部

    当浏览器向 Web 服务器发出请求时，会发送若干 HTTP 头。有时访问这些信息会很有用。我们可以先使用 $_SERVER 关联数组。该数组包含 Web 服务器提供的各种信息，其中包括客户端发送的 HTTP 头。请看以下程序，它会显示 $_SERVER 数组的所有值：

    <?php
     // displays variables related to the web server
   // send simple text
  header("Content-type: text/plain");
   // associative array path $_SERVER
     reset($_SERVER);
     while (list($clé,$valeur)=each($_SERVER)){
      echo "$clé : $valeur\n";
    }//while
?>

    我们将此代码保存到 headers.php 中，并使用浏览器访问该 URL：

    我们获取了多项信息，包括浏览器发送的 HTTP 头部。这些是与以 HTTP 开头的键关联的值。让我们来分析一下上面获取的部分信息：

    HTTP_ACCEPT
    Web 客户端支持的文档类型
    HTTP_ACCEPT_CHARSET
    文档中接受的字符集
    HTTP_ACCEPT_ENCODING
    文档支持的编码类型
    HTTP_ACCEPT_LANGUAGE
    文档支持的语言类型
    HTTP_CONNECTION
    与服务器的连接类型。Keep-Alive：服务器在发送响应后必须保持连接打开
    HTTP_KEEP_ALIVE
    ? 最大连接时长
    HOST
    客户端查询的主机
    HTTP_USER_AGENT
    客户端标识
    REMOTE_ADDR
    客户端的IP地址
    REMOTE_PORT
    客户端使用的通信端口
    SERVER_PROTOCOL
    服务器使用的 HTTP 协议
    REQUEST_METHOD
    客户端使用的请求方法（GET 或 POST）
    QUERY_STRING
    附加在请求 URL 后的查询字符串（GET 方法）

    通过对前一个程序的代码稍作修改，我们可以仅提取 HTTP 头部：

     while (list($clé,$valeur)=each($_SERVER)){
      // header HTTP ?
    if(strtolower(substr($clé,0,4))=="http")
          echo substr($clé,5)." : $valeur\n";
    }//while

    3.10. 会话跟踪

    3.10.1. 问题

    一个 Web 应用程序可能包含服务器与客户端之间多次表单交互。该过程的工作原理如下：

    步骤 1

    1. 客户端 C1 与服务器建立连接并发出初始请求。
    2. 服务器向客户端 C1 发送表单 F1，并关闭在步骤 1 中建立的连接。

    步骤 2

    1. 客户端 C1 填写表单并将其发回服务器。为此，浏览器与服务器建立新的连接。
    2. 服务器处理表单 1 中的数据，据此计算出信息 I1，将表单 F2 发送给客户端 C1，并关闭在步骤 3 中建立的连接。

    步骤 3

    1. 步骤 3 和 4 的循环在步骤 5 和 6 中重复。在步骤 6 结束时，服务器将已收到两个表单 F1 和 F2，并已根据它们计算出信息 I1 和 I2。

    当前的问题是：服务器如何跟踪与客户端 C1 相关的信息 I1 和 I2？这个问题被称为跟踪客户端 C1 的会话。为了理解其根本原因，让我们来分析一个同时为多个客户端提供服务的 TCP-IP 服务器应用程序的示意图：

    在典型的 TCP-IP 客户端-服务器应用程序中：

    • 客户端与服务器建立连接
    • 通过此连接与服务器交换数据
    • 连接由双方中的一方关闭

    该机制的两个关键点是：

    1. 为每个客户端建立一个单独的连接
    2. 该连接将贯穿服务器与其客户端对话的整个过程

    服务器之所以能在任何时刻识别正在交互的客户端，正是因为连接——或者说“通道”——将服务器与客户端紧密相连。由于该通道专用于特定客户端，因此通过该通道接收的所有数据均来自该客户端，而通过该通道发送的所有数据也将送达该客户端。

    HTTP 客户端-服务器机制遵循上述模型，唯一的区别在于客户端与服务器的交互仅限于一次往返通信：

    • 客户端向服务器建立连接并发出请求
    • 服务器发送响应并关闭连接

    如果在时间 T1，客户端 C 向服务器发出请求，它将获得连接 C1，该连接将用于单次请求-响应交互。如果在时间 T2，同一客户端向服务器发出第二次请求，它将获得连接 C2，该连接与连接 C1 不同。 对于服务器而言，用户 C 的第二次请求与其初始请求并无区别：在两种情况下，服务器都将该客户端视为新客户端。若要建立客户端 C 与服务器之间不同连接的关联，客户端 C 必须被服务器“识别”为“常客”，且服务器必须检索其关于该常客的信息。

    让我们设想一个运作方式如下所示的政府机构：

    • 仅有一条队列
    • 设有多个服务窗口。因此，可以同时为多名顾客提供服务。当某个窗口有空位时，顾客便会离开队列前往该窗口办理业务
    • 如果这是顾客的首次到访，柜台工作人员会给他们一张印有号码的号牌。顾客只能提出一个问题。一旦得到答复，他们必须离开柜台并回到队尾。柜台工作人员会将顾客的信息记录在标有该号码的档案中。
    • 当轮到该顾客时，服务柜员可能与上次不同。柜员会索要其代币，并调出带有该代币编号的档案。顾客再次提出请求，获得答复，相关信息会被添加到其档案中。
    • 如此循环往复……随着时间推移，客户将获得所有请求的答复。不同请求之间的关联通过代币及其关联的档案得以维持。

    客户端-服务器Web应用程序中的会话跟踪机制与上述示例的工作原理类似：

    • 客户端发出首次请求时，Web 服务器会向其发放一个令牌
    • 客户端将在后续每次请求中提交该令牌以进行身份验证

    令牌可以采用多种形式：

    • 表单中的隐藏字段
      • 客户端发起首次请求（服务器能识别该请求，因为客户端此时没有令牌）
      • 服务器发送响应（一个表单），并将令牌放置在表单内的隐藏字段中。此时，连接被关闭（客户端带着令牌退出会话）。服务器可能已将相关信息与该令牌关联起来。
      • 客户端通过重新提交表单发起第二次请求。服务器从表单中提取令牌。随后，服务器可通过该令牌访问首次请求期间计算出的信息，从而处理客户端的第二次请求。 新信息被添加到与该令牌关联的文件中，第二份响应被发送给客户端，连接第二次关闭。令牌已被放回响应表单中，以便用户在下次请求时能够提供它。
      • 以此类推……

    该技术的主要缺点在于，令牌必须放置在表单中。如果服务器的响应不是表单，则无法再使用隐藏字段方法。

    • Cookie 方法
      • 客户端发出首次请求（服务器通过客户端未持有令牌来识别此请求）
      • 服务器通过在 HTTP 头部添加一个 Cookie 进行响应。这通过 HTTP Set-Cookie 命令实现：

    Set-Cookie: param1=value1;param2=value2;....

    其中 param1、param2 等为参数名称及其对应值。这些参数中将包含令牌。通常情况下，Cookie 中仅包含令牌，服务器会将其他信息存储在与该令牌关联的文件夹中。接收该 Cookie 的浏览器会将其存储在磁盘上的文件中。服务器响应后，连接即被关闭（客户端携带着其令牌退出会话）。

    • （待续）
      • 客户端向服务器发出第二次请求。每次向服务器发送请求时，浏览器都会检查其拥有的所有 Cookie，以确认是否包含来自该服务器的 Cookie。如果存在，则将其发送给服务器，形式始终为 HTTP 命令——即 Cookie 命令，其语法与服务器使用的 Set-Cookie 命令类似：

    Cookie: param1=value1;param2=value2;....

    在浏览器发送的HTTP头部中，服务器将找到该令牌，从而识别客户端并检索与其关联的信息。

    这是最常用的令牌形式。它有一个缺点：用户可以配置浏览器拒绝Cookie。这样一来，这些用户就无法访问使用Cookie的Web应用程序。

    • URL 重写
      • 客户端发出首次请求（服务器能识别出这是首次请求，因为客户端没有令牌）
      • 服务器发送响应。该响应包含用户必须使用的链接，以便继续使用应用程序。在每个链接的 URL 中，服务器会以 URL;token=value 的形式添加令牌。
      • 当用户点击其中一个链接以继续使用应用程序时，浏览器会向 Web 服务器发送请求，并在 HTTP 头中包含所请求的 URL（URL;token=value）。随后，服务器便能检索到该令牌。

    3.10.2. 用于会话跟踪的 PHP API

    接下来我们将介绍用于会话跟踪的主要方法：

    session_start()
    启动当前请求所属的会话。如果该请求尚未属于任何会话，则会创建一个会话。
    session_id()
    当前会话的标识符
    $_SESSION[$var]
    存储会话数据的字典。支持读写
    session_destroy()
    删除当前会话中包含的数据。这些数据在当前的客户端-服务器交互中仍然可用，但在下一次交互中将不可用。
